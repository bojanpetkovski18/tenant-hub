### v2 risks
- **Row-level security and pooled connections (M14).** A setting that outlives its transaction would leak a tenant, and the v1 app runs as a superuser, which bypasses every policy. Mitigation: transaction-local settings, a separate non-superuser runtime role used by the tests too, a leak test on one physical connection, and a startup refusal when the role can bypass.
- **Policies slowing queries (M14).** Mitigation: `EXPLAIN` on the hot queries and the M10 load test repeated, with the overhead recorded.
- **Background work that runs twice or never (M15, M16, M20).** Mitigation: `SKIP LOCKED` claims, leases, unique keys for generated rows, and tests with two workers and a moving clock.
- **Drag and drop under the strict CSP (M17).** Mitigation: verify on the production build first, as D023 did for the CDK overlay; the keyboard path does not depend on dragging. Outcome: the CDK's drag resets are a runtime `<style>`, now in `styles.css`; no CSP violation while dragging on the production image (D046).
- **A new identity and cookie scheme (M18).** Mitigation: the portal matrix, cross-scheme refusal tests, mutation checks, and the strongest model for the milestone. Outcome: the matrix (22 cases) and the cross-scheme tests pass; with the handlers' client filters removed the database's client policy alone holds, and with it removed too 6 cases fail (D040).
- **Native image libraries in the chiseled runtime image (M19).** Mitigation: choose the library with its dependencies checked in the real image before building on it; the owner decides if it is not clear-cut. Outcome: the owner chose SkiaSharp with its dependency-free Linux build after ImageSharp's licence-key check ruled it out; the production image decoded and re-encoded the seed's 13 photos at startup (D043).
- **Outbound requests to customer URLs (M21).** Mitigation: address checks at connection time, no redirects, tests with a fake resolver.
- **Scope.** Ten milestones with new UI each. Mitigation: the v2 cut list, and the v1 list, form and dialog patterns reused.

## Risks
- **Isolation harness complexity (M03).** Enumerating endpoints and building the cross-tenant matrix generically is the hardest part. Mitigation: start with a plain table of cases and automate the enumeration only for the coverage checks.
- **Concurrency tests that flake (M06, M08).** Mitigation: deterministic two-transaction tests alongside the parallel HTTP tests, and repeated runs recorded.
- **Scope creep in the UI.** Mitigation: the list, form and dialog patterns are built once in M04 and reused.
- **Free hosting limits (M12).** Mitigation: the demo also runs with one command locally and in Codespaces.
